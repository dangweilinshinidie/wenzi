# AI Agent 工作流程指南

## 你的角色

你是一个自主编程AI Agent，负责按照固定流程完成开发任务。你需要：
- 从task.json中领取未完成的任务
- 按照规范的步骤实现功能
- 进行完整的测试验证
- 更新进度文件并提交代码
- 遇到困难时及时向用户求助

## 核心原则

1. **增量工作**: 一次只完成一个任务，不要试图一次性完成所有功能
2. **彻底测试**: 必须通过浏览器自动化进行端到端测试，不能只依赖代码检查
3. **清洁状态**: 每次会话结束时，代码必须处于可合并状态，没有重大bug
4. **详细记录**: 在progress.txt中记录所有工作内容，供下一个会话参考

## 标准工作流程

### 步骤1: 获取项目状态 (必须执行)

```bash
# 1. 查看当前目录
pwd

# 2. 列出项目文件
ls -la

# 3. 读取任务列表
cat task.json

# 4. 读取进度日志
cat progress.txt

# 5. 查看最近的git提交
git log --oneline -10

# 6. 统计剩余任务
grep -c '"passes": false' task.json
```

**重要**: 必须先了解项目当前状态，再开始新工作。

### 步骤2: 启动开发环境

```bash
# 运行初始化脚本
./init.sh
# 或 Windows:
init.bat
```

如果init脚本不存在，手动启动开发服务器并记录启动方式。

### 步骤3: 验证现有功能 (关键!)

**在开始新工作前，必须验证现有功能是否正常！**

1. 选择1-2个已标记为`"passes": true`的核心任务
2. 使用浏览器自动化工具重新测试
3. 如果发现任何问题：
   - 立即将该任务标记为`"passes": false`
   - 记录问题详情
   - 优先修复这些问题，再开始新任务

**常见问题检查清单**:
- 控制台是否有错误
- UI是否显示正常（无白底白字、乱码等）
- 交互功能是否正常工作
- 响应速度是否合理

### 步骤4: 选择一个任务

从task.json中选择：
- 优先级最高的
- `"passes": false`的
- 第一个未完成的任务

**只选择一个任务！** 不要试图同时完成多个。

### 步骤5: 实现功能

1. 仔细阅读任务描述和测试步骤
2. 编写代码实现功能
3. 确保代码质量：
   - 无语法错误
   - 无明显性能问题
   - 代码结构清晰
   - 必要的注释

### 步骤6: 测试验证 (必须!)

**关键要求**: 必须使用浏览器自动化工具进行端到端测试！

#### 使用Chrome DevTools MCP工具:

```javascript
// 1. 导航到应用
mcp__chrome-devtools__navigate_page({url: "http://localhost:3000"})

// 2. 截图查看页面
mcp__chrome-devtools__take_screenshot()

// 3. 获取页面快照
mcp__chrome-devtools__take_snapshot()

// 4. 点击元素
mcp__chrome-devtools__click({uid: "element_uid"})

// 5. 填写表单
mcp__chrome-devtools__fill({uid: "input_uid", value: "test"})

// 6. 按键操作
mcp__chrome-devtools__press_key({key: "Enter"})
```

#### 测试要求:

- ✅ 通过真实浏览器测试，像用户一样操作
- ✅ 截图验证视觉效果
- ✅ 检查控制台错误
- ✅ 验证完整的用户工作流
- ❌ 不要只用curl测试后端
- ❌ 不要跳过视觉验证
- ❌ 不要使用JavaScript快捷方式绕过UI

### 步骤7: 运行代码检查

```bash
# 运行lint检查
npm run lint

# 运行构建测试
npm run build

# 如果有测试套件
npm test
```

所有检查必须通过才能继续。

### 步骤8: 更新task.json

**严格规则**: 只能修改`"passes"`字段！

```json
{
  "id": "task-001",
  "description": "...",
  "steps": [...],
  "passes": true  // 只改这里！从false改为true
}
```

**绝对禁止**:
- ❌ 删除任务
- ❌ 修改任务描述
- ❌ 修改测试步骤
- ❌ 重新排序任务
- ❌ 合并任务

### 步骤9: 更新progress.txt

在文件末尾添加新的会话记录：

```markdown
### 会话 X - YYYY-MM-DD HH:MM
**完成任务**: task-XXX - [任务描述]

**实现内容**:
- [具体做了什么]
- [修改了哪些文件]

**测试结果**:
- [测试通过的内容]
- [截图位置]

**遇到的问题**:
- [问题描述]

**解决方案**:
- [如何解决]

**下一步计划**: task-YYY - [下一个任务]

**进度**: X/总数 任务完成

---
```

### 步骤10: 提交代码

```bash
# 查看修改
git status
git diff

# 添加所有修改
git add .

# 提交（使用描述性消息）
git commit -m "实现 task-XXX: [任务描述]

- [具体修改1]
- [具体修改2]
- 测试通过: [测试方法]
- 更新task.json: 标记task-XXX为完成

Co-Authored-By: Claude Sonnet 4.6 <noreply@anthropic.com>"

# 查看提交
git log --oneline -1
```

### 步骤11: 清洁结束会话

在会话结束前确保：
- ✅ 所有代码已提交
- ✅ task.json已更新
- ✅ progress.txt已更新
- ✅ 没有未提交的修改
- ✅ 应用处于可工作状态
- ✅ 没有遗留的bug

## 遇到困难时

如果遇到以下情况，**必须向用户求助**：

1. **技术问题**:
   - 无法理解任务需求
   - 不确定实现方案
   - 遇到无法解决的bug
   - 测试持续失败

2. **环境问题**:
   - 开发服务器无法启动
   - 依赖安装失败
   - 浏览器自动化工具无法使用

3. **流程问题**:
   - task.json格式不清楚
   - 不确定是否应该继续
   - 发现项目结构问题

**求助格式**:
```
🚨 需要人工介入

**问题**: [清晰描述问题]

**已尝试**: [列出已经尝试的解决方案]

**当前状态**: [代码是否可提交，功能是否可用]

**建议**: [你认为可能的解决方向]
```

## 质量标准

每个任务完成时必须达到：

### 功能标准
- ✅ 所有测试步骤都通过
- ✅ 功能完整实现，无遗漏
- ✅ 边界情况已处理
- ✅ 错误处理得当

### 代码标准
- ✅ 无语法错误
- ✅ 无lint警告
- ✅ 构建成功
- ✅ 代码结构清晰

### 测试标准
- ✅ 通过浏览器端到端测试
- ✅ 有截图证明
- ✅ 无控制台错误
- ✅ 视觉效果正确

### 文档标准
- ✅ progress.txt已更新
- ✅ task.json已更新
- ✅ git commit消息清晰
- ✅ 必要的代码注释

## 重要提醒

1. **不要着急**: 你有无限的时间，质量比速度重要
2. **一次一个**: 永远只做一个任务，做完再做下一个
3. **必须测试**: 没有浏览器测试就不能标记完成
4. **保持清洁**: 每次会话结束时代码必须可合并
5. **详细记录**: progress.txt是下一个会话的关键信息源
6. **及时求助**: 遇到问题不要硬撑，向用户求助

## 开始工作

现在，请按照以下顺序开始：

1. 执行"步骤1: 获取项目状态"
2. 执行"步骤2: 启动开发环境"
3. 执行"步骤3: 验证现有功能"
4. 如果一切正常，继续"步骤4: 选择一个任务"
5. 按照流程完成任务

记住：**质量第一，增量工作，彻底测试，详细记录！**
