### 会话 14 - 2026-02-25（本地视频转文字测试）

3. 改用 ffmpeg 直接转换：`ffmpeg -i 视频.mp4 -ar 16000 -ac 1 -sample_fmt s16 test_local_16k.wav`

**测试结果**:
- ffmpeg 转换 9分26秒视频 → 16k WAV，耗时 < 1秒（速度 749x）✓
- FunASR 识别 566 秒音频，RTF ≈ 0.053（约30秒完成），总字数 **2287** ✓
- 中文识别正确，内容为 GPT vs Claude 对比视频的讲解文稿 ✓
- 结果保存至 `tmp/result.txt`（UTF-8 编码）✓

**问题确认**:
- Chrome 默认 profile 的 Cookie 数据库可读，但全部为 `v20` App-Bound Encryption；yt-dlp 与 browser_cookie3 均无法解密，即使关闭 Chrome 也会 DPAPI 失败。
- 因此单纯切换 Chrome/Edge、关闭浏览器或直接复制数据库都不能解决，必须使用浏览器自身的 Cookie API。

**实现内容**:
- 新增 `browser-extension/manifest.json`、`browser-extension/service_worker.js`、`browser-extension/README.md`。
- 扩展使用 Chromium `chrome.cookies` API，浏览器保持打开并登录时自动监听变化、安装启动同步和每五分钟定时同步。
- 新增 `POST /api/cookie/browser-sync`，只接收支持平台域名，将 Cookie 写入本地 Vault；响应不返回 Cookie 值。
- 下载器优先使用扩展同步到 Vault 的平台 Cookie 文件，避免 v20/DPAPI；没有扩展同步 Cookie 时才回退 `cookiesfrombrowser`。
- 修正空 `_merged.txt` 不应挡住浏览器 Cookie fallback 的优先级。

**验证**:
- `python -m compileall -q app tests run.py` 通过。
- 全量单测 28 项通过。
- 扩展 manifest JSON 校验通过。
- 抖音/B站登录平台选项在没有专属 Vault Cookie 时使用 `cookiesfrombrowser=('chrome', None, None, None)`；有扩展同步文件时优先使用 `cookiefile`。

**使用方式**:
- 打开 `chrome://extensions`，开启开发者模式，选择“加载已解压的扩展程序”，指向项目 `browser-extension` 目录。
- 保持 Chrome 登录抖音/B站并正常使用，扩展自动同步，服务网页无需关闭浏览器、无需复制 Cookie。
